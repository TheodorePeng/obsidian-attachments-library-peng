# Attachments Library Peng 开发需求简报

日期：2026-10-23  
状态：需求记录保留；2026-10-24 已按下述决策实现源码和自动测试，真实 Vault 验收另行记录。
依据：[原 ChatGPT 会话](https://chatgpt.com/c/6ad92ff3-7958-83e9-aa42-9b3c1b7e18ee)、本地 Fork 源码、Obsidian 官方文档。

## 1. 项目目标

在 Attachments Library 的基础上，开发一个利用 Obsidian 原生 Bases 的附件管理增强插件，统一处理附件索引、元数据、图片跳转、引用分析与人工清理。

主要使用环境是 Mac 上的本地 Vault，现有测试场景为 Math Peng。图片保存在 Vault 内，普通笔记继续通过原有图片嵌入语法使用图片。插件独立提供核心管理能力，不依赖 Bases CMS 等其他社区插件。

## 2. 用户需要解决的问题

- 图片分散在不同文件夹，现有单目录监控不适合按整个 Vault 管理。
- 希望为图片保存来源 URL、描述、OCR 文字等信息，但普通笔记的图片引用位置只展示图片。
- OCR 内容可能包含长文本、Markdown 排版和 LaTeX 数学公式，需要长期保存、编辑和检索，也方便 AI Agent 读取。
- 在普通笔记中看到图片后，希望直接进入它的元数据文档，减少查找文件和反向链接的步骤。
- 希望在统一管理界面预览、筛选、选择和删除附件，不必反复使用左侧文件列表。
- 未被引用的图片需要先预览，再由用户选择是否删除；没有引用并不代表没有保留价值。

## 3. 已明确的六项核心需求

### R1：全 Vault 文件类型白名单索引

允许按可配置的扩展名白名单，对整个 Vault 内符合条件的文件建立索引，不再局限于一个附件目录。用户明确举过 `.png`、`.jpg` 等例子，并希望后续支持自定义类型。

首版默认全 Vault，白名单限常见图片、音频、视频与 PDF，允许增减附件扩展名。Markdown 及其变体、Base 和 Canvas 会从白名单中移除，并在候选检查中再次硬性拒绝。

实现约束：排除插件生成的索引文档，防止递归索引；兼容旧索引；区分不同目录下的同名文件；补建时保留已有元数据和正文。

### R2：独立 Markdown 元数据文档

延续原插件“一份附件配一份 Markdown 文档”的结构。Sidecar Markdown 只是这种配套文件的名称，不是另一款需要安装的插件。

- 简短字段保存在 Properties，例如标题、来源、标签。
- 长篇 OCR、公式和说明保存在 Markdown 正文，沿用 Obsidian 的编辑与检索能力。
- 普通笔记继续直接嵌入原始图片，不必附带显示元数据正文，也不要求每次手工增加元数据链接。
- 元数据采用普通文件保存，方便用户、脚本和 AI Agent 读取。

OCR 识别由用户自行处理。插件负责管理识别结果，不需要接入 OCR 模型或服务。

官方文档明确将 Properties 定位为简短、独立的信息项，不支持 Markdown 富文本，因此不应把完整 OCR 正文塞入属性字段。[Properties 文档](https://obsidian.md/help/properties)

### R3：图片右侧居中的元数据入口

在普通笔记中嵌入已索引的图片时，图片右边线居中提供可自动隐藏的小入口，点击定位并打开对应的索引 Markdown 文档。

不要求改写已有图片引用语法。阅读模式、实时预览中的表现需要分别验证；同一图片出现在不同笔记、使用短链接或完整路径时，应解析到同一份元数据。

普通点击在当前页打开索引，中键打开索引新标签，Command 点击打开出处；保留原生 Command 选项时打开索引新标签。Command 悬浮按钮只预览索引，图片本体保持原图预览。没有索引时点击预览单项创建，悬浮不创建文件。

### R4：插件自带或管理原生 Bases 附件库

延续 `.base` 文件与元数据 Markdown 的组合，在插件提供的管理体验中完成附件预览、筛选、元数据访问、单选或多选，以及后续批量操作。

用户希望直接增强 Attachments Library，不依赖 Bases CMS 才能完成核心流程。已有 `.base` 中的用户自定义视图、排序和筛选应被保留。

建议优先验证官方 `registerBasesView()` 自定义视图路线，复用 Bases 的查询结果并添加所需交互。这是实现方向，不代表已经验证原生表格的选中项和删除按钮能够直接被接管。[官方 Bases 视图开发指南](https://docs.obsidian.md/plugins/guides/bases-view)

### R5：从管理界面联动删除索引与原附件

选中一份或多份索引 Markdown 后，可以同时删除它们及对应的原附件。核心结果是用户在附件库中完成成对管理，无需分别寻找两类文件。

建议提供明确的“删除附件及元数据”操作：先展示文件清单和引用情况，再确认执行；同时保留仅删除元数据的选择。具体按钮和菜单位置属于后续交互设计。

实现时需要处理：共享附件的提示、取消后不改动文件、遵循回收站设置、批量去重、双向事件避免循环，以及部分失败时报告实际结果。

不能把“收到索引已删除的事件后再删图片”当作完整的删除前确认机制。是否增强原生删除入口，需要另行验证。

### R6：孤儿附件筛选、预览与人工批量清理

识别没有被实际内容文件使用的附件，在管理界面中筛选出来，提供缩略图预览、选择和批量删除。检测结果用于辅助判断，不自动清空所有未引用附件。

判定必须排除插件为管理附件而自动生成的引用，例如配套索引中的 `attachment` 链接及预览嵌入。否则每张已索引图片都会被误认为仍在使用。

普通笔记中的实际引用需要计入。Canvas 及其他文件类型的覆盖规则要明确验证；未扫描完成、引用解析失败或覆盖不完整时，应显示待检查状态，不能直接认定可删除。

可考虑派生的引用文件数、孤儿候选状态和人工保留标记。字段名及持久化方式尚未确定；这些属于实现建议，不是用户已经确认的数据协议。

## 5. 必须纳入设计的兼容边界

1. **旧索引与正文保全。** 改为全 Vault 路径后，不能因位置推导变化而重复生成索引，也不能覆盖已有 OCR、公式、来源和用户视图。
2. **关联准确。** 同名附件、索引移动、附件重命名以及关联失效时，不得仅凭文件名猜测要打开或删除的文件。
3. **索引范围不等于引用来源范围。** Markdown 不进入附件白名单；它与 Canvas、Base 一起作为全 Vault 引用来源。删除权限还需要独立的引用、保留、关联和新鲜度检查。
4. **引用状态有时效。** 添加或移除业务引用后，需要更新状态；执行删除前应重新检查，不能只依赖旧统计。
5. **中文与数学内容。** 应保留中文路径、中文标签和 LaTeX。新建标签清洗保留 Unicode 中文，不批量清洗旧标签。
6. **版本与显示模式。** 原清单的最低版本声明不能直接作为新增 Bases 视图或图片工具栏功能的兼容承诺，需要重新核实并运行验证。

## 6. 已批准实施顺序

详细实施约束见 [实施计划](implementation-plan.zh-CN.md)，实际验证结果见 [验收记录](implementation-acceptance-2026-10-24.md)。

1. **统一索引与关联基础。** 统一附件白名单、排除规则和旧路径兼容，硬性排除 Markdown，保证补建和文件变更不丢内容。
2. **打通元数据访问。** 完成正文模板与图片跳转入口，在 Mac 的实际编辑流程中验证。
3. **完成引用分析。** 明确有效引用口径，产出可刷新、可解释的孤儿候选结果。
4. **整合 Bases 管理与删除。** 增加预览、多选、筛选及成对删除，使用前一步的引用分析完成删除前检查。

## 7. 验收要点

- 白名单内的分散文件可被索引，排除目录和索引文档不会递归产生新索引；重复补建不覆盖内容。
- 旧索引仍能被找到；不同目录的同名图片不会串联；移动和重命名后关联与正文保持完整。
- 普通笔记保持原有图片嵌入方式，能通过图片按钮进入正确元数据，阅读模式和实时预览分别验证。
- OCR 正文及公式可正常编辑、渲染与检索；停用插件后文件内容仍可读取。
- 不安装 Bases CMS，也能完成已承诺的预览、筛选、选择和管理操作。
- 自身索引引用不会阻止孤儿识别；新增业务引用后，附件不再被标为孤儿候选；未知状态不会混入可清理项。
- 批量删除可以预览并取消，能区分共享附件，失败时报告准确结果，且不会删除未选中的文件。

代码检查应配合独立测试 Vault 验证，尤其覆盖真实 Bases 选择与删除、图片渲染模式、Canvas 引用和文件恢复。源码或单元测试通过，不能替代这些运行验收。

## 8. 已确定的实施选择

- Markdown 永不作为附件候选；新建配套 Markdown 仅保存元数据和正文。
- 图片普通点击当前索引、Command 点击出处、中键索引新标签；缺失索引时明确确认单项建立。
- 同一个 Base 保留原生表格与 CMS，追加官方注册的专用管理视图；最低版本声明为 1.13.1。
- 引用扫描覆盖 Markdown、Canvas、Base；未知目标保护，人工保留进入首版。
- 旧索引原地采用，不进行批量搬迁；CMS 原生 Delete 保持自身语义，成对删除只在本插件明确命名的操作中执行。

本次明确不包含 OCR 识别服务、图床、Spotlight 搜索或图片 EXIF/XMP 写入开发。它们曾在探索中出现，但没有成为此次 Fork 的已确认实现需求。简报也不据“更新较少”推断上游已经停止维护。


## 9. 2026-10-24 的 1.1.0 历史实现记录

以下保留 1.1.0 实施历史；当前 1.2.0 调整见后文。第 4 节的原插件基线同样作为历史对照保留。

- 独立 ID `attachments-library-peng`，显示名 Attachments Library Peng，版本 1.1.0，最低 Obsidian 1.13.1。
- 新安装默认全 Vault 白名单；可选单目录。Markdown、Base、Canvas、隐藏路径和 Library 永久排除附件索引。它们仍按相应规则作为引用来源。
- 首次启动仅只读建立关联和引用状态，不改旧索引或 Base。完整补建必须预览确认；显式单项创建只写该项。完整扫描成功后启用增量自动创建及全库派生字段采用。
- 旧索引的 attachment 与 _filePath 一致才关联；保持旧位置和正文。新索引使用完整 Vault 路径避免同名串联。关联冲突、多索引和大小写碰撞保护。附件改名保持索引位置，外删附件保留索引，外删索引保留附件。
- 新索引用 Properties 存短字段，正文含受控预览、OCR 与说明；中文标签和 LaTeX 正文保留。status 沿用阅读状态，引用状态使用独立 al_* 字段。
- 图片单按钮：左键当前索引、Cmd/Ctrl 左键来源 URL、中键索引新标签、右键菜单；标准 hover-link 始终指向索引，Hover Editor 无侵入接管。可设回原生 Cmd/Ctrl 内链行为。阅读和 Live Preview 均有独立实现入口与模拟测试。
- 原生 Bases 自定义视图使用 this.data 查询结果、排序、分组，默认 60 项分页；图片懒加载，其他媒体显式单项预览。换页或过滤变化清空选择。旧 Base 备份后幂等追加 owned 视图，保留既有全局条件、table、CMS 与未知配置。
- 引用服务覆盖 Markdown 正文/前言、Canvas file/text、Base 显式常量链接；直接附件与索引入链按来源集合去重。只排除可明确识别的管理引用；缓存未就绪、动态目标、解析歧义保持 unknown。未知项不能清理。
- 删除统一 prepare/execute，预览后 freshscan、代次、目标 hash/mtime/size 和 dirty editor 二次核对。受保护项显示原因并跳过；成对删除附件先于索引，使用 Vault 本地 .trash。中途变化、部分失败和日志失败会停止后续处理，不永久删除、不自动重试。
- 日志保存在插件 config 目录的 deletion-log.json，保留原路径、步骤、结果和恢复目录，重启后可审计；没有自动续删。

用法、边界和验证命令见 [README](../README.md)。实际安装与运行结果由另行的验收记录说明；自动覆盖率通过不等同真实 UI、Hover Editor 或回收站恢复验收。此次实现没有运行 release、commit、push。
